# 데이터 표준화 가이드 (시나리오 데모용)

> 출처 표시: SYNTHETIC_SCENARIO_V1_NOT_OFFICIAL — 이 문서는 PoC 시연을 위해 작성한 가상의 내부 지침이며, 실제 공공기관의 공식 표준화 지침이 아닙니다. `data/scenario_catalog.json`과 짝을 이루는 문서로, 같은 4개 도메인(수N7·명V100·율N5,2·코드C2)과 12개 시나리오 용어를 전제로 작성했습니다.

## 1. 목적 및 적용 범위

이 가이드는 신규 표준 용어를 신청·등록할 때 담당자와 시스템(AI 에이전트 포함)이 함께 준수해야 할 작성 규칙을 정한다. 표준 용어는 **표준단어 → 표준도메인 → 표준용어 → 표준사전**의 순서로 구성되며, 이 가이드는 그중 표준용어 작성 단계에 적용한다.

신규 용어 등록 신청은 다음 두 가지를 모두 충족해야 검토 대기(PENDING_REVIEW) 상태로 접수된다.

1. 기존 표준사전에 동일하거나 의미가 같은 용어가 없을 것 (중복 검사 — 별도 로직으로 자동 처리)
2. 이 가이드의 작성 규칙을 위반하지 않을 것 (본 문서의 대상)

## 2. 표준용어 작성 규칙 (자동 검증 항목)

> 이 절의 규칙은 naming.py의 형태소·정규식 검사가 이미 정확하게 자동 검증합니다. 이 절을 근거로 새로 판단하거나 "위반"이라고 재확인하지 마세요 — 이 절에 실린 예시 용어("값" 등)가 실제로 여기에 걸리는 경우는 대부분 다른 절(2-2)의 사유 때문입니다.

- 표준용어는 하나 이상의 표준단어를 의미가 통하는 순서로 조합한 한글 명사(구)로 작성한다.
- 한글 명사형으로 끝나야 하며, 조사(을/를/이/가/은/는)나 어미로 끝날 수 없다. (예: "…시간", "…열량", "…점수"처럼 명사로 끝나면 이 규칙에 위배되지 않는다 — 마지막 글자가 조사 목록에 있는 음절 그 자체와 일치할 때만 위반이다.)
- 영문 약어를 병기하는 경우 한글 표준용어 뒤에 괄호로 붙인다. 예: "체질량지수(BMI)".
- 이미 존재하는 표준용어와 정의가 실질적으로 동일한 경우, 새 용어로 등록하지 않고 기존 용어의 동의어로 편입한다.
- 서로 다른 성격의 값(권장량 vs 실제 측정량, 총량 vs 비율, 기준 시점이 다른 값 등)은 이름만으로 구분되도록 수식어를 명확히 한다. 예: "일일권장열량"과 "일일섭취칼로리"는 "권장"과 "섭취"라는 서로 다른 표준단어로 구분된다.

### 2-1. 용어 전체 길이 기준 (자동 검증 항목)

> 이 소절도 코드가 글자 수를 세어 자동으로 검증합니다. 재계산하거나 재판단하지 마세요.

- **최소 길이**: 공백을 제외한 글자 수가 2자 이상이어야 한다. 한 글자짜리 용어("값", "수", "율" 등)는 그 자체로는 등록할 수 없다.
- **최대 길이**: 공백을 포함한 전체 글자 수가 20자를 넘을 수 없다. 글자 수는 한글 음절 하나를 1자로 계산한다(자음·모음 분리 계산 아님).
- **표준단어 조합 개수 권장 기준**: 표준단어를 5개 이내로 조합하는 것을 권장한다. 6개 이상을 조합하면 대부분 20자 제한을 초과하게 되어 실질적으로 반려 사유가 된다.
- **경계값 예시** (동작 테스트용):
  - 정확히 20자, 통과: "성인남녀별일일권장영양소섭취기준량환산값" (20자)
  - 21자, 반려: "성인남녀별일일권장영양소섭취기준량환산값치" (21자 — 최대 길이 초과)
  - 1자, 반려: "값" (최소 길이 미달)
  - 2자, 통과: "나이" (최소 길이 충족)

## 2-2. 용어 단어 선택 원칙 (사람 또는 AI의 의미 판단이 필요한 항목)

> 이 절은 코드로 자동 검증되지 않습니다. 형태소·길이·문자 종류가 전부 정상이어도, 아래 기준은 의미를 보고 판단해야 합니다 — 이 절만이 실제로 반려 판단이 필요한 유일한 절입니다.

- 아래 목록의 단어와 이름 전체가 정확히 같을 때만 위반이다: "값", "정보", "데이터", "항목", "구분", "내용", "사항". 이 목록에 없는 단어는, 설령 뜻이 넓게 느껴지더라도 이 규칙 위반이 아니다 — 마음대로 목록을 넓히거나 유사어까지 확장하지 말 것.
- 목록 단어라도 앞에 대상을 특정하는 다른 표준단어가 붙어 복합어가 되면(예: 가상의 예시로 "체온값") 더 이상 위반이 아니다 — 대상이 이미 정해져 있기 때문이다.
- 판정 절차: (1) 후보 이름 전체 문자열이 위 7개 목록 중 하나와 정확히 일치하는가? 아니라면 즉시 compliant=true. (2) 일치한다면 그때만 위반으로 판정한다. "지수", "점수", "시간", "값" 같은 음절로 끝난다는 이유만으로 위반 판정을 내리지 말 것 — 이름 전체가 목록 단어 자체와 같은지만 본다.

## 3. 영문 약어 작성 규칙

한글 표준용어는 그에 대응하는 **영문 약어를 반드시 함께 등록**해야 한다. 실무자가 영문 약어를 직접 작성하기 어려운 경우, 아래 규칙에 따라 AI가 후보를 추천하고 담당자가 최종 확정한다.

1. **국제 표준 약어 우선 채택**: 이미 국제적으로 통용되는 약어가 있으면 그것을 그대로 채택한다. 예: 체질량지수 → `BMI`, 기초대사열량 → `BMR`, 나이 → `AGE`.
2. **표준단어 단위 축약 후 언더스코어 연결**: 통용 약어가 없으면, 표준용어를 구성하는 표준단어 각각을 3~5자로 축약해 언더스코어(`_`)로 연결한다. 축약 시 모음을 우선 생략하고 자음을 살린다.
3. **표기 규칙**: 영문 대문자와 언더스코어만 사용한다. 전체 길이는 20자를 넘지 않는다. 숫자는 축약어 뒤에만 붙일 수 있다.
4. **고유성**: 하나의 영문 약어는 하나의 표준용어에만 대응해야 한다. 이미 다른 용어가 쓰고 있는 약어는 재사용할 수 없다.
5. **일관성**: 같은 표준단어는 같은 문서/사전 내에서 항상 같은 방식으로 축약한다. 예: "일일"은 항상 `DAILY`로, "열량"은 항상 `CAL`로 축약한다 — 어떤 용어에서는 `DLY`, 다른 용어에서는 `DAILY`처럼 혼용하지 않는다.

## 4. 도메인 분류 기준

용어의 **마지막 표준단어**가 도메인을 결정한다.

| 마지막 단어 패턴 | 배정 도메인 | 설명 |
|---|---|---|
| 열량, 칼로리, 나이 등 정수형 수치 | 수N7 | 정수 7자리 |
| 지수, 비율, 율(率) 등 소수점 비율 | 율N5,2 | 전체 5자리, 소수 2자리 |
| 명(名) 등 명칭·식별 문자열 | 명V100 | 문자열 최대 100자 |
| 코드 | 코드C2 | 문자 2자리 분류 코드 |

마지막 단어만으로 도메인이 애매한 경우, 비교 가능한 기존 용어들의 실제 도메인 사용 비율(비교군 통계)을 참고하여 담당자가 최종 선택한다.

## 5. 동의어 및 유사 용어 처리 원칙

- 정의가 실질적으로 동일하면(SAME_MEANING) 새로 등록하지 않고 기존 용어의 동의어로만 추가한다.
- 관련은 있으나 범위·기준이 달라 구분해야 하는 경우(RELATED_BUT_DISTINCT), 별도 표준용어로 등록하되 두 용어의 차이를 정의에 명확히 기술해야 한다.
- 정의가 불충분하거나 모호해 자동으로 판단할 수 없는 경우(UNCERTAIN), 담당자 검토를 거쳐야 하며 시스템이 임의로 승인·반려를 결정하지 않는다.
